ELIZA: A Computer Program for the Study of Natural Language Communication Between Man and Machine (1966)

Before this

In the 1960s there was no large body of digital text, and the learning machines of the day, such as the perceptron, could sort simple shapes but came nowhere near the size of language. If a computer was to hold a conversation, every response had to be written in advance. Weizenbaum, at MIT, wrote ELIZA to run on a time-shared computer that people reached by typewriter terminal. Its best-known script, DOCTOR, played a non-directive psychotherapist, a clever choice: that kind of therapist mostly reflects your own words back, so the program could seem to listen without knowing anything about the world.

In the 1960s there was no large digital text corpus, and the learning methods of the day, such as the single-layer perceptron, handled only simple pattern classification, so any conversational behavior had to be specified explicitly. Weizenbaum built ELIZA on MIT's MAC time-sharing system. Its best-known script, DOCTOR, imitated a Rogerian psychotherapist, a style that mostly reflects the user's own statements back and so needs no knowledge of the world.

In the walk

A different kind of park: a formal garden. Every path was cut by hand, and a signpost at each junction names the pattern it answers. Nothing is worn; nobody counted anything. The walker matches what it was handed against the signs and follows the path the matching sign points to.

In the mechanism

ELIZA's script was a list of keywords and decomposition patterns, each with reassembly rules that reused parts of the input. "I am X" could become "How long have you been X?" No probabilities, no data: rules written by hand. The same approach ran through decades of symbolic AI.

A script is a ranked set of rules \((k, d, r)\): a keyword \(k\), a decomposition pattern \(d\) that splits the input \(x\) into segments \(s_1,\dots,s_m\), and a reassembly template \(r\) that builds the reply from them:

\[y = r\big(d(x)\big)\]

The reply is a deterministic function of the input: no probabilities and no parameters fit to data. The same approach ran through decades of symbolic AI.

A closer look: one signpost, read closelydecomposition and reassembly

A script is a list of keywords, each with a rank and one or more decomposition patterns. A pattern splits the input into numbered pieces; a reassembly rule builds the reply from those pieces. The paper's own example:

InputIt seems that you hate me
Pattern(0 YOU 0 ME), where 0 matches any run of words
Pieces(1) It seems that · (2) you · (3) hate · (4) me
Reassembly(WHAT MAKES YOU THINK I 3 YOU)
ReplyWhat makes you think I hate you

Pronouns are swapped on the way through, "my" for "your" and "I" for "you", so copied pieces read naturally. If several keywords appear, the highest-ranked one wins. If none does, ELIZA falls back on a content-free prompt such as "Please go on", or brings up something saved from earlier: a sentence that began "my…" could return later as "Earlier you said your…".

In the garden picture, each keyword is a signpost and each reassembly rule is a path someone cut to a fixed destination. Nothing about the garden is learned. Every response that ever appears was, in shape, typed in by a person.

A script is a list of ranked keywords. Each keyword has decomposition patterns that split the input into numbered segments, and reassembly templates that build the reply from those segments. The paper's example:

InputIt seems that you hate me
Pattern(0 YOU 0 ME), where 0 matches any sequence of words
Segments(1) It seems that · (2) you · (3) hate · (4) me
Template(WHAT MAKES YOU THINK I 3 YOU)
OutputWhat makes you think I hate you

Pronouns are transformed during the copy ("my" to "your", "I" to "you"). When several keywords match, the highest-ranked one is used. When none does, the program emits a generic prompt such as "Please go on", or retrieves a stored earlier input: a sentence beginning "my…" could return later as "Earlier you said your…".

The output space is exactly \(\{\,r(d(x))\,\}\) over the script's rules, plus the fallbacks. Every possible response was, in form, written by the script author.

What it changed

ELIZA left a name behind: the ELIZA effect, people's readiness to credit a program with understanding. Weizenbaum was disturbed by it. In his 1976 book Computer Power and Human Reason he recalled his secretary, who had watched him build the program, asking him to leave the room so she could talk to it in private.

The cut-path method carried on for decades in symbolic AI and the expert systems of the 1970s and 80s. It is easy to inspect and fails abruptly: one step off the cut paths and there is nothing underfoot.

The "ELIZA effect" names users' tendency to attribute understanding to such a program. Weizenbaum found it troubling; in Computer Power and Human Reason (1976) he recalled his secretary asking him to leave the room so she could talk with it privately.

Hand-written rules remained the dominant approach in symbolic AI and the expert systems of the 1970s and 80s. They are transparent and brittle: inputs outside the rules get no meaningful response.
