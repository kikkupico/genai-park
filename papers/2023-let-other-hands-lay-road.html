Before this

A walker knows only what was worn into its trails during training. Facts after that date are missing, rare facts are faint, and exact arithmetic is unreliable, since it is done by reading blazes. Scouting doesn't help with any of this: you can't reason your way to a phone number.

A model's knowledge is limited to what its parameters absorbed during training: nothing after the training cutoff, unreliable recall of rare facts, and imprecise arithmetic. Generating more reasoning tokens doesn't help with any of these: missing information can't be derived.

Formally: \(p_\theta(y\mid x)\) can only use what is in \(\theta\) and in the context. Retrieval and tools add a document or result \(d\) to the context, giving \(p_\theta(y\mid x, d)\).

In the walk

Midway, the walker can call for help: a search, a calculator, a database. Another hand lays a stretch of road with the result, and the walker carries on from the new end. It still has no map. What it gets is more road, not a view of the park. A chat works the same way: each of your messages is road laid by another hand.

In the mechanism

Retrieval-augmented generation fetches relevant passages and adds them to the model's input. Toolformer trained a model to write API calls into its own text, with the results spliced in. Either way the model reads the whole road again, including the new stretch.

\[p(y\mid x) \approx \sum_{d\,\in\,\text{top-}k} p_\eta(d\mid x)\,p_\theta(y\mid x, d),\qquad p_\eta(d\mid x)\propto \exp\big(E_D(d)^\top E_Q(x)\big)\]

Retrieval-augmented generation finds passages by inner product of embeddings and marginalizes over them. Toolformer writes API calls into its own text, with the results spliced in. Either way the model attends over the whole context again, including the inserted text.

A closer look: two ways to get road laidretrieval and self-supervised tool learning

Retrieval (2020). Before writing, a retriever turns the question into a vector, finds the passages from a large document collection whose vectors are closest, and places them in the road ahead of the question. The walker then answers with those passages behind it. The paper trained the retriever and the writer together, and could update the model's knowledge by swapping the document index, without retraining the walker.

Tools (2023). Toolformer let the walker decide, midway, to call for help by writing the call into its own text. The results are spliced in and the walk continues. From the paper:

Out of 1400 participants, 400 (or [Calculator(400 / 1400) → 0.29] 29%) passed the test.

It learned this mostly on its own. The model proposed possible calls throughout ordinary text, the calls were run, and a call was kept as a training example only if the result made the following words easier to predict. A 6.7-billion-parameter model trained this way beat much larger models on several tasks requiring facts or arithmetic.

In both cases the walker still has no map. It never sees the database or the search engine, only the stretch of road the result is written into.

RAG (2020). A dense retriever embeds the query \(x\) and the documents, and retrieves the top-\(k\) documents by \(E_D(d)^\top E_Q(x)\) from a large index. The generator conditions on the query plus each passage, and the two models are combined by marginalizing over \(d\), per sequence or per token:

\[p_{\text{seq}}(y\mid x) \approx \sum_{d} p_\eta(d\mid x)\prod_i p_\theta(y_i\mid x, d, y_{<i}),\qquad p_{\text{tok}}(y\mid x) \approx \prod_i \sum_{d} p_\eta(d\mid x)\,p_\theta(y_i\mid x, d, y_{<i})\]

The retriever's query encoder and the generator were fine-tuned jointly, and the model's knowledge could be updated by replacing the index without retraining.

Toolformer (2023). The model learns to emit API calls inline in its own output; the calls are executed and their results inserted into the text before generation continues. An example from the paper:

Out of 1400 participants, 400 (or [Calculator(400 / 1400) → 0.29] 29%) passed the test.

Training data was generated self-supervised: the model sampled candidate calls at positions in ordinary text, the calls were executed, and a call was kept only if inserting its result reduced the loss on the following tokens: \(L^-_i - L^+_i \ge \tau_f\), where \(L^+_i\) is the weighted loss with the call and its result, and \(L^-_i\) the lower of the losses with no call or with the call but no result. A 6.7B-parameter model trained this way outperformed much larger models on several knowledge and arithmetic tasks.

In both cases, external information enters only through the context window. The model never accesses the index or tool directly, only the tokens of the result.

What it changed

Tool use became a standard feature: assistants that search, run code and call services, and agents that work through long tasks by alternating walking with other hands laying road. The context window became a workspace, and a chat is the same thing: every message you send is road laid by another hand.

The more of the world's text is written this way, the more the next walkers will learn from it.

Tool use became a standard capability: function calling, code execution, web search, and agent loops that interleave generation with tool calls over long tasks. The context window became the working memory for these systems, and a multi-turn chat is the same structure, with each user message inserted into the context.

As generated text spreads, it also enters the data later models are trained on.
